# nexclash v0.1.7

Download `nexclash-0.1.7.zip`, unzip it, create a virtual environment, then install
`requirements.txt`. Run `python nexclash.py patch MyGame.z80`; add `--nex` to keep the
playable NEX outputs as well as the NXC patch. Bring your own game files. Loader and card
setup: https://github.com/jattree/nxc. GPL-3.0-or-later.

This release brings the current toolkit and agent workflow to download users. Engine,
shared-hook and game support changes since v0.1.5 are included; see STATUS.md and games/
for each game's software evidence, hardware coverage and remaining work.

- Known games take a recognition shortcut; `survey --full` requests the full analysis.
- New engines compare the R register. Agent instructions use meaningful session boundaries,
  targeted dependency reading and a source freeze before final verification.
- Failed builds return nonzero exit codes. Selftest counts subprocess failures and retains
  their diagnostic logs. Patch commands reject stale sprite output from an earlier run.
- Contribution imports validate file hashes and original baselines before writing, require a
  clean checkout and restore prior files on a failed write. Linked Git worktrees are supported.
- Exports include dependencies, configuration, workflow and skill changes. Unsupported source
  changes stop export; `--exclude PATH` records an intentional omission of an unrelated file.
- After refreshing main, export uses the current merge base. Stale `--base` overrides are
  refused. Virtual environments, caches and generated output are pruned before scanning.

Compatibility: older contribution archives without original hashes can add new files, but
cannot replace existing files. Regenerate them with this version or use a pull request.
Unsupported required binary artwork still needs review through a PR; player game data is
never included in contribution archives or release packages.

Validation scope: GitHub CI, documentation/learning checks, 23 workflow/archive regression
tests, the Chuckie Egg canary and the full tools suite. The representative Fantasy World
Dizzy base/printer rebuilds matched their recorded hashes. Optional checks requiring missing
reference files or JNext configuration were skipped. Broad game re-verification/stamping was
intentionally excluded from this workflow maintenance release; no new hardware validation
is claimed. Per-game evidence and limitations remain in the game records and notes.
